# Proposed service pilot

Select one service and a bounded set of recurring ticket categories. Use approved internal tooling and permissions; this public repository contains synthetic data only.

1. Agree on severity and escalation policy before changing queue order.
2. Record ticket wait states, owner, SME assistance, resolution and reopen events.
3. Capture reasoning from resolved examples; review context/prerequisites and test procedures with another engineer.
4. Run retrieval suggestions in advisory mode and record useful, wrong and missed matches.
5. Compare like-for-like categories over a defined period. Track SME waiting, reopened tickets, resolution time and approved-procedure use; do not attribute shifts to the tool without considering ticket mix and staffing.
6. Convert stable diagnostics into read-only checks only after verifying the procedures.

Treat knowledge capture and mentoring as planned team work. Avoid turning SME flags into individual performance scores. Reserve experts for uncertain cases, review and system improvements.
